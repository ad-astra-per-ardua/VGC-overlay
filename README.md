# SDVX 대회 송출 오버레이

의존성 없음. Node 18 이상이면 바로 돕니다.

```bash
node server.js
# 오버레이  http://localhost:8787/overlay.html
# 컨트롤    http://localhost:8787/control.html
```

CSS와 JS는 HTML 안에 인라인되어 있습니다. 외부 파일 로딩이 없으므로
경로 문제로 스타일이 깨질 일이 없습니다.

## 폴더

```
server.js
state.json
public/overlay.html
public/control.html
assets/           bg.png, 팀 로고, 선수 아이콘, jackets/
videos/           선수별 녹화본 (p1.mp4 …)
```

파일이 평평하게 섞여 있어도 서버가 찾아냅니다. 없는 파일은 기동 시
`[누락]` 으로 콘솔에 뜨고, 요청이 404 나면 `404 /경로` 가 찍힙니다.

## 안 될 때 확인 순서

1. 서버 콘솔에 `404` 줄이 찍히는지 — 찍히면 그 파일이 없는 것
2. 브라우저 F12 → Console 에 빨간 에러가 있는지
3. F12 → Network 에서 `api/events` 가 pending 상태로 살아있는지
   — 끊겨 있으면 컨트롤 조작이 오버레이에 전달되지 않습니다
4. 컨트롤 패널 우하단 표시가 "연결됨" 인지

## OBS 설정

브라우저 소스 하나만 추가합니다. 씬 전환은 필요 없습니다.

- URL: `http://localhost:8787/overlay.html`
- 너비 1920 / 높이 1080
- "소스가 보이지 않을 때 화면 종료" 체크 해제 (영상 재생이 끊깁니다)
- 컨트롤 패널은 다른 노트북·태블릿에서 `http://<송출PC IP>:8787/control.html`

## 화면

| 뷰 | 내용 |
|---|---|
| `songs` | 좌우 3곡씩 + 중앙 라운드 엠블럼. 밴된 곡에 BANNED 브러시가 덮임 |
| `match` | 4분할 영상 + 상단 점수 미터 |

선곡과 밴은 같은 화면입니다. 뷰를 전환하지 않고 BANNED 마크만 얹히므로
진행 중에 카드가 다시 그려지지 않습니다. 다시 보여주려면 "밴 애니 다시"
버튼을 누르세요.

예전 상태값(`select`, `ban`)은 `songs` 로 자동 흡수되니 기존 state.json 을
그대로 써도 됩니다.

`assets/bg.png` 를 넣으면 배경 장식이 깔립니다. 없으면 주황 그라데이션만
나옵니다.

## 영상 싱크

선수들에게 받은 녹화본은 시작 시점이 제각각입니다.

1. 각 슬롯에 `/videos/p1.mp4` 형태로 경로 입력
2. "처음부터" 로 4개 동시 재생
3. 어긋난 선수의 `offsetMs` 조정 — 양수면 그 선수 영상을 앞으로 감습니다
4. 기준점은 곡 시작음이나 첫 노트가 잡히는 프레임으로

`offsetMs` 는 state.json 에 저장되므로 한 번 맞춰두면 유지됩니다.

브라우저 재생이라 코덱은 H.264 + AAC (mp4) 를 권장합니다.

```bash
ffmpeg -i 원본.mkv -c:v libx264 -preset fast -crf 20 -c:a aac videos/p1.mp4
```

## 점수 미터

지금은 컨트롤의 슬라이더로 수동 조작합니다. `match.meter` 는 -1(좌팀 압도) ~
+1(우팀 압도) 범위입니다.

나중에 OCR 워커를 붙일 때는 서버에 이것만 POST 하면 됩니다.

```
POST /api/state
{ "match": { "meter": -0.32, "label": "+96,074" } }
```

오버레이 코드는 건드릴 필요가 없습니다.

# 점수 미터 자동화

실시간 OCR 을 돌리지 않습니다. 녹화본에서 **방송 전에 미리** 시간별 점수를
뽑아 JSON 으로 저장해두고, 방송 중에는 재생 위치로 배열을 조회만 합니다.
이분 탐색이라 프레임당 수십 ns, 체감 딜레이가 없습니다.

인식이 틀려도 방송 전에 검수하고 고칠 수 있다는 게 실시간 방식 대비
가장 큰 장점입니다.

## 준비물

```bash
pip install opencv-python numpy
cd tools
```

## 1) 점수 영역 좌표 찾기

```bash
python sdvx_score.py frame --video ../videos/p1.mp4 --at 30 --out frame.png
```

`frame.png` 를 열어 점수 영역의 x, y, w, h 를 재고 `config.json` 에 적습니다.

SDVX 점수는 **앞 4자리가 큰 글자, 뒤 4자리가 작은 글자**로 크기가 다릅니다.
8칸 균등 분할하면 깨지므로 영역을 둘로 나눠 각각 4자리씩 잡으세요.

```json
{
  "fields": [
    { "x": 1200, "y": 50, "w": 120, "h": 40, "digits": 4, "weight": 10000 },
    { "x": 1325, "y": 58, "w": 70,  "h": 28, "digits": 4, "weight": 1 }
  ],
  "fps": 5,
  "max_score": 10000000
}
```

숫자에 최대한 딱 맞게 자르세요. 여백이 많으면 정규화가 어긋납니다.

## 2) 숫자 템플릿 학습

프레임을 뽑고 그 시점의 실제 점수를 알려주면 자릿수별로 잘라 저장합니다.

```bash
python sdvx_score.py frame --video ../videos/p1.mp4 --at 12 --out f.png
python sdvx_score.py learn --frame f.png --config config.json --digits 01704523
```

큰 글자와 작은 글자는 **템플릿을 따로 모읍니다**(`templates/f0`, `templates/f1`).
양쪽 모두 0~9 가 찰 때까지 다른 시점으로 몇 번 반복하세요. 부족한 숫자는
콘솔에 표시됩니다. 한 번 만들어두면 같은 해상도·레이아웃의 다른 선수
영상에도 그대로 재사용할 수 있습니다.

## 3) 타임라인 추출

```bash
python sdvx_score.py run --video ../videos/p1.mp4 --config config.json \
                         --out ../videos/p1.scores.json
```

4명분을 각각 돌립니다. 끝나면 최종 점수가 출력되니 **리절트 화면과 대조**하세요.
다르면 ROI 좌표가 틀린 것입니다.

점수가 단조 증가한다는 제약으로 오인식·역행·범위초과를 걸러내므로,
중간에 몇 프레임 놓쳐도 결과가 튀지 않습니다.

## 4) 오버레이에 연결

컨트롤 패널 → 경기 중 슬롯에 `/videos/p1.scores.json` 입력 → "자동 미터" 켜기.

"최대 점수차" 는 바가 끝까지 차는 기준값입니다. 기본 150,000 이고, 실제
경기 로그를 보고 조정하세요. 너무 크면 바가 안 움직여 심심합니다.

자동 미터를 켜면 수동 슬라이더는 잠깁니다. 인식이 이상한 구간이 있으면
자동을 끄고 수동으로 넘기면 됩니다.

## 밴 진행 방식

밴 버튼은 누르는 즉시 송출에 나가지 않습니다. 대기열에 쌓였다가
**"밴 일괄 적용"** 을 눌러야 한 번에 반영됩니다.

- `BAN` → `밴 예정` (주황 점선) → 적용하면 `BANNED`
- 이미 밴된 곡을 누르면 `해제 예정`
- 대기 건수는 버튼 옆에 표시되고, "선택 취소" 로 되돌립니다
- 양쪽 팀 곡을 한 번의 요청으로 보내므로 오버레이는 한 번만 갱신됩니다

적용하면 그 자리에서 BANNED 마크가 그어집니다. 화면 전환이 없습니다.

오버레이는 곡 목록이 실제로 바뀌었을 때만 다시 그립니다. 점수를 올리거나
팀명을 고쳐도 선곡 카드는 그대로 있고, 곡 제목을 수정하면 카드가 다시
튀어나오지 않고 글자만 바뀝니다.

## 테마: Black & Gold

`Black_and_Gold_Pitch_Deck_by_Slidesgo.pptx` 의 실제 테마 XML을 뜯어 팔레트와
서체를 그대로 가져왔습니다.

| 값 | 색상 | 출처 |
|---|---|---|
| 배경 | `#000000` | theme1 dk1 (마스터1 실제 배경) |
| 골드(메인 강조) | `#E9C78C` | theme1 lt1 — 타이틀 텍스트 실사용 색 |
| 크림(보조 텍스트) | `#FAECD3` | theme1 dk2 — 부제 텍스트 실사용 색 |

서체는 덱에서 실제로 가장 많이 쓰인 것 기준입니다.

- **Josefin Sans** — 영문 라벨(ARENA BATTLE, ROUND, EVOLVE, BANNED, NO SIGNAL,
  랭크 표기, k/M 점수차 라벨)에 적용. Google Fonts 로 자동 로드되어 별도 설치가
  필요 없습니다.
- **넥슨Lv2고딕** — 곡명·선수명·팀명 등 한글/일본어 텍스트에 적용. PPT에
  임베드된 폰트라 재배포 라이선스 문제로 웹폰트로 번들하지 않았습니다.
  **송출 PC에 이 폰트가 설치되어 있어야** 정확히 나오고, 없으면 자동으로
  Pretendard 로 대체되어 레이아웃은 안 깨지지만 서체 느낌은 달라집니다.
  넥슨 공식 사이트(공식 배포 페이지)에서 무료로 받아 설치할 수 있습니다.

## 통합 영상 모드 (4명이 한 영상 안에 이미 배치된 경우)

게임 클라이언트 자체의 4레인 관전 화면처럼, 4명이 **이미 한 영상 안에 싱크
맞춰 배치**되어 있는 경우를 위한 모드입니다. 이 경우 선수마다 파일을 따로
받을 필요가 없습니다.

내부적으로는 `<video>` 하나만 숨겨서 디코딩하고, 화면에 보이는 4칸은
`<canvas>` 가 매 프레임 그 영상에서 각자 다른 사각형만 오려 그립니다.
그래서 파일 4개를 따로 트는 것보다 디코딩 부하가 적습니다.

### 사용법 — 배치가 매 경기 고정일 때 (권장)

편집 단계에서 1P가 항상 맨 왼쪽에 오도록 정렬해두셨다면, 캘리브레이션 없이
프리셋 버튼 한 번으로 끝납니다.

1. 컨트롤 패널 "경기 중 — 영상" 섹션에서 **"모드: 통합 영상 1개"** 클릭
2. 통합 영상 경로 입력 (예: `/videos/all4.mp4`)
3. **"프리셋: 가로 4분할"** 클릭 — 1번 슬롯이 화면 맨 왼쪽 25%, 2번이 그다음
   25%, … 순서로 자동 채워집니다. 4레인이 세로로 나뉜(2×2) 레이아웃이면
   **"프리셋: 2×2 격자"** 를 대신 누르세요
4. 슬롯의 선수명·팀·랭크만 매 경기 채우면 끝 — 좌표는 다시 안 건드려도 됩니다

`state.json` 기본값 자체도 가로 4분할로 미리 채워뒀으니, 프리셋 버튼조차
안 눌러도 대부분 그대로 맞을 겁니다.

### 사용법 — 배치가 매번 다르거나, 정확한 픽셀 위치가 필요할 때

`crop-calibrator.html` 을 여세요 (컨트롤 패널의 링크 클릭, 또는
`http://localhost:8787/crop-calibrator.html` 직접 접속). 로컬 영상 파일을
열고, 슬롯 버튼을 고른 뒤 화면에서 드래그로 사각형을 그리면 좌표가 표에
뜹니다. **JSON 복사** 로 통째로 가져와도 되고, 표의 숫자를 컨트롤 패널
칸에 하나씩 옮겨도 됩니다.

### 두 모드 비교

| | 선수별 파일 4개 (기존) | 통합 영상 1개 (신규) |
|---|---|---|
| 필요한 것 | `slot.video`, `slot.offsetMs` | `match.combinedVideo`, `slot.crop` |
| 싱크 보정 | 선수마다 ms 단위로 맞춤 | 불필요 (이미 한 타임라인) |
| 디코딩 부하 | 파일 4개 동시 재생 | 파일 1개만 디코딩 |
| 점수 타임라인 | 슬롯별로 그대로 사용 | 슬롯별로 그대로 사용 (변경 없음) |

두 모드는 언제든 전환 가능하고, 전환해도 곡 목록·밴·팀 점수 등 다른 상태는
그대로 유지됩니다.

## 점수 미터 실시간 갱신 (최적화 내역)

초기 구현은 100ms 스로틀 + 계단식 조회라 접전 상황에서 숫자가 뚝뚝 끊겨
보였습니다. 세 가지를 고쳤습니다.

**1. 샘플 사이 선형 보간**
타임라인은 5fps(200ms 간격)로 추출되어 있어서, 그대로 읽으면 갱신 주기를
아무리 높여도 200ms마다 툭툭 점프합니다. 앞뒤 샘플을 시간 비율로 섞어
연속적인 값을 만들었습니다. 60fps 기준 프레임당 점프폭이 40,000 → 3,334 로
약 12배 부드러워졌습니다.

**2. 갱신 주기: 100ms → 매 프레임**
바 위치는 이제 60fps 로 갱신됩니다. 다만 숫자 라벨은 80ms(초당 ~12회)만
다시 만듭니다 — 문자열 포맷팅이 이 루프에서 가장 비싼 작업이고, 숫자가
60fps 로 바뀌면 사람 눈에는 읽히지 않고 깜빡이기만 하기 때문입니다.

**3. 조회·DOM 비용 절감**
- 탐색 커서를 슬롯별로 기억해 이분 탐색 대신 한두 칸 전진으로 끝냅니다.
  커서 저장은 `Map` 이 아니라 `Int32Array` 입니다 — `Map.get/set` 오버헤드가
  900개 배열 이분 탐색보다 비싸서 처음엔 오히려 느려졌었습니다
- `getElementById` 결과를 캐시하고, 값이 실제로 바뀐 항목만 DOM 에 씁니다
- CSS 트랜지션을 `.35s` → `.08s` 로 줄였습니다. 값 자체를 매 프레임 보간해
  넣으므로 긴 트랜지션은 화면을 0.35초 뒤처지게 만들 뿐이었습니다

### 측정 결과

3분 경기 · 60fps · 4슬롯 기준 점수 조회 비용은 프레임당 약 0.92µs 로,
16.67ms 프레임 예산의 **0.006%** 수준입니다.

jsdom 으로 1초(60프레임) 실측 시 바 위치는 60개 고유값(매 프레임 갱신),
라벨은 12개 고유값(스로틀 적용)이 확인되었습니다.

## 성능 최적화 2차 (인식 도구 + 오버레이)

### 점수 인식 도구 — 병목은 인식이 아니라 디코딩

프로파일링 결과 전체 시간의 **94%가 프레임 디코딩**(`grab`)이었고, 템플릿
매칭(인식)은 2.4%에 불과했습니다. 인식 알고리즘을 아무리 빨리 해도 총 시간은
2% 남짓만 줄어들기 때문에 인식 쪽은 손대지 않았고, 디코딩을 공략했습니다.

**1) 통합 영상 단일 패스 추출 (~3.7배, 실측)**
`config.json` 에 `"players"` 배열로 4명의 ROI 를 모두 지정하면, 영상을 한 번만
디코딩하면서 전원의 점수를 동시에 추출합니다. 기존에는 같은 영상을 4번
디코딩해야 했습니다. 20초 합성 영상 기준 58.3s → 15.6s (3.74배), 4명 결과
모두 개별 실행과 완전 동일함을 확인했습니다.

**2) 멀티프로세싱 (`--workers N`, 기본 = CPU 코어 수)**
영상을 시간 구간으로 쪼개 프로세스별로 나눠 디코딩합니다. 구간 경계를 샘플
간격(stride)의 배수에 맞춰 단일 프로세스와 결과가 완전히 동일합니다
(workers=2 로 검증 완료). 디코딩이 병목이라 코어 수에 거의 비례해 빨라집니다.
단, 이 검증 환경이 1코어라 병렬 속도 향상 수치는 실측하지 못했습니다 —
실제 PC(멀티코어)에서 확인하세요. 두 최적화는 곱으로 작동합니다:
8코어에서 4인 통합 영상이면 이론상 기존 대비 ~30배.

### 오버레이 렌더링

**경기중 화면 (통합 영상 캔버스)**
- `getBoundingClientRect` 를 매 프레임 4회 부르던 것 제거 — 레이아웃 강제
  계산이라 프레임 예산을 갉아먹는 주범이었습니다. 크롭 좌표·캔버스 크기·ctx 를
  "그리기 계획"으로 미리 평탄화해 두고, 상태 변경·리사이즈 때만 재구축합니다
- 일시정지 중 같은 프레임을 60fps 로 다시 그리던 낭비 제거
  (`currentTime` 변화 감지)
- 캔버스 컨텍스트 `alpha: false` — 영상으로 꽉 차는 캔버스라 투명도 합성
  단계를 건너뛸 수 있습니다

**점수 미터**
- `width`/`left` 갱신 → `transform: scaleX/translateX` 로 전환. width 변경은
  매 프레임 레이아웃(reflow)을 일으키지만 transform 은 GPU 합성만으로 처리되어
  60fps 갱신에도 메인 스레드 부담이 없습니다
- 일시정지 중 재계산 스킵 (시각이 안 변하면 결과도 같으므로)

**공통**
- SSE 로 상태가 올 때마다 값이 같아도 무조건 DOM 에 쓰던 곳들에 변경 감지
  가드 추가 (textContent 는 같은 값이어도 텍스트 노드 교체가 실제로 일어남)
- 선곡 카드·피드에 `contain: layout style` — 내부 변화(밴 마크 삽입 등)가
  이웃 요소의 레이아웃 재계산으로 번지지 않게 격리

## 확정 워크플로우 — 매 경기 런북

전처리(영상 편집)에서 4개 영상을 1x4 로 합치고 싱크까지 맞추는 것이 확정이므로,
오프셋(offsetMs) 관련 기능은 전부 무시하면 됩니다. 매 경기 할 일:

**최초 1회만 (레이아웃 고정이므로 재사용)**
1. 합쳐진 영상에서 프레임 추출:
   `python sdvx_score.py frame --video all4.mp4 --at 30 --out f.png`
2. `config.combined.example.json` 을 `config.json` 으로 복사하고,
   f.png 를 열어 4명의 점수 좌표(x, y, w, h)를 실측값으로 수정
3. 템플릿 학습(0~9 모일 때까지 몇 프레임 반복):
   `python sdvx_score.py learn --frame f.png --config config.json --digits <실제점수8자리>`
4. 오버레이 크롭은 이미 기본값(가로 4분할)이라 손댈 것 없음

**매 경기**
1. 편집 완료된 통합 영상을 `videos/` 에 넣기
2. 점수 타임라인 추출 (한 번의 디코딩으로 4명 동시):
   `python sdvx_score.py run --video ../videos/all4.mp4 --config config.json --out ../videos/all4.scores.json`
   → `all4.p1.scores.json` ~ `all4.p4.scores.json` 4개 생성
3. 컨트롤 패널에서: 통합 영상 경로 + 슬롯별 타임라인 경로(p1~p4) + 선수명 입력
4. 끝. 크롭·오프셋·ROI 는 건드릴 일 없음

## 스코어 미터 체감 품질 — 송출 PC(RTX 3070 Ti) 기준 설정

**1) 타임라인 해상도 5fps → 20fps (config 기본값 상향)**
`grab()` 이 어차피 전 프레임을 디코딩하므로, 추출 fps 를 올려도 늘어나는 건
인식 비용뿐입니다. 실측: 4배 촘촘한 데이터에 +34% 시간. 보간이 50ms 간격의
실데이터 사이만 메우게 되어 콤보 구간의 점수 가속·감속이 실제 모양대로
표현됩니다. (5fps 는 200ms 를 직선으로 이어 미세한 리듬감이 뭉개졌습니다)

**2) GPU 디코딩 (기본 활성화)**
RTX 3070 Ti 의 NVDEC 전용 디코더가 CPU 대신 디코딩을 맡습니다. 디코딩이
전체의 94%이므로 효과가 큽니다. 실패 시 자동으로 CPU 폴백이라 끌 필요는
없지만 `--no-hwaccel` 로 강제 비활성화할 수 있습니다.
i5-13600KF(14코어)와 조합: `--workers` 기본값이 코어 수라 그대로 두면 됩니다.

**3) 역전 순간 펄스**
리드 팀이 뒤바뀌는 순간 점수차 라벨이 살짝 튀며 강조됩니다(0.5초).
transform 만 쓰는 컴포지터 전용 애니메이션이라 성능 비용이 없습니다.
초기 진입(경기 시작 직후 리드 확정)에는 발동하지 않고 실제 역전에만 반응합니다.

**4) OBS 설정 (코드 밖 — 이게 제일 중요할 수 있음)**
- 오버레이 브라우저 소스 속성에서 **FPS 를 60 으로** (사용자 지정 프레임
  속도 체크 후 60). 기본 30 이면 위의 60fps 보간이 절반으로 깎입니다
- OBS 설정 → 고급 → **브라우저 소스 하드웨어 가속** 켜기 — 오버레이
  렌더링을 3070 Ti 가 맡습니다
- 출력(방송/녹화) 프레임레이트도 60fps 로

## STRATEGY (스트레티지)

대회 전체(1~4라운드 통틀어) **한 번만** 사용하는 선곡 교체 카드입니다.

### 규칙 (코드로 강제됨)
1. 상대 선곡 중 하나를 대상으로 지정
2. 밴과 STRATEGY 는 같은 곡에 중복 불가 — 밴된 곡의 STR 버튼, STR 대상 곡의
   밴 버튼이 각각 비활성화됩니다
3. 후보 3곡 중 하나로 대체하거나, 리셋으로 원곡을 유지할 수 있습니다.
   **리셋을 골라도 사용 횟수는 소진**됩니다

### 운영 순서
1. 컨트롤 "STRATEGY" 섹션에 후보 곡 3개를 미리 입력 (경기 전 준비)
2. 상대 곡 목록에서 **STR** 버튼 클릭 → 오버레이에 조준 연출 재생
3. **"다음 단계"** 클릭 → 후보 3장이 셔플되며 공개
4. **1번/2번/3번** 중 하나 또는 **리셋** 클릭 → 확정
5. 필요하면 **"진행 취소"** 로 패널을 닫습니다 (확정된 교체는 유지)

### 연출
- **조준(aim)**: 스코프 링이 바깥에서 회전하며 대상 카드로 수축 → 십자선이
  뻗음 → LOCKED 표시. 대상 카드는 붉게 맥동합니다
- **공개(cards)**: 후보 3장이 아래에서 떠오른 뒤 좌우로 흔들리는 셔플 3회
- **확정(result)**: 고른 카드만 골드 테두리로 확대, 나머지는 흑백으로
  사그라듦. 하단에 "선곡 대체" 또는 "원곡 유지" 표시

연출을 다시 보여주려면 **"STR 애니 다시"** 를 누르세요.
잘못 소진한 경우 **"사용 기록 초기화"** 로 되돌릴 수 있습니다
(이미 교체된 곡 자체는 되돌아가지 않으니 곡 목록에서 직접 수정하세요).

## 라운드별 포맷 (2v2 / 1v1 분기)

라운드마다 인원과 곡 수가 다릅니다. 컨트롤 최상단 **"라운드 포맷"** 섹션에서
버튼 하나로 곡 슬롯 수와 경기 화면 분할이 한꺼번에 맞춰집니다.

| 라운드 | 형식 | 곡 수(각 진영) | 선곡 배치 | 경기 화면 |
|---|---|---|---|---|
| R1 · R3 | 2v2 | 3곡 | 세로 3장 | 가로 4분할 |
| R2 | 1v1 메가믹스 | 5곡 | **오각형** | 가로 2분할 |
| R4 | 1v1 싱글 | 2곡 | 세로 2장 (카드 확대) | 가로 2분할 |

**오버레이는 곡 개수만 보고 배치를 자동으로 바꿉니다.** 컨트롤에서 곡을
추가·삭제해도 즉시 반영되므로, 포맷 버튼을 쓰지 않고 직접 개수를 맞춰도 됩니다.

- 2곡 → `duo` : 카드 높이 260px, 자켓·제목 확대 (2장뿐이라 여백을 채움)
- 3곡 → `trio`: 기존 레이아웃
- 5곡 → `penta`: 정오각형 꼭짓점 배치. 카드는 250×104 컴팩트형이고
  밴 칼선·조준경도 카드 크기에 맞춰 축소됩니다

경기 화면 분할도 슬롯 수를 따라갑니다(2명=2분할, 4명=4분할). 1v1 일 때는
화면비가 과하게 늘어나지 않도록 좌우에 15% 여백이 들어갑니다.

### 라운드별 진행 메모
- **R2 (메가믹스)**: 각 선수 5곡. STRATEGY 는 여기서도 한 곡에 쓸 수 있습니다
  (대회 통틀어 1회 제한은 그대로).
- **R4 (싱글)**: 각 2곡을 가져와 서로 하나씩 밴합니다. 기존 밴 기능을 그대로
  쓰되, 양쪽에서 한 곡씩만 밴하면 됩니다.

## 전체 감사 기록 (버그 수정)

기능 추가가 누적된 뒤 전 구간을 감사해 아래 4건을 잡았습니다. 모두
"정상 경로에서는 안 드러나지만 방송 중 조작 순서에 따라 터지는" 종류입니다.

**1) STRATEGY 패널이 경기 화면까지 따라옴**
`renderStrategy` 가 선곡 뷰에서만 호출되어, STRATEGY 진행 중 경기 화면으로
전환하면 후보 카드 패널이 영상 위에 그대로 남았습니다. 뷰가 선곡이 아닐 때
패널을 강제로 닫도록 수정.

**2) 슬롯 축소 시 옛 타임라인 잔존**
4인(2v2) → 2인(1v1) 으로 줄여도 3·4번 슬롯의 점수 타임라인이 메모리에
남아, 나중에 같은 인덱스가 다시 생기면 옛 데이터가 잠깐 섞일 수 있었습니다.
슬롯 재구성 시 범위 밖 타임라인·커서를 함께 정리하도록 수정.

**3) 라운드 포맷 변경이 STRATEGY 대상을 고아로 만듦**
3곡에서 3번 곡을 조준한 채 R4(2곡) 프리셋을 누르면, 존재하지 않는 곡을
가리킨 상태로 "다음 단계" 가 진행됐습니다. 대상이 사라지면 진행을 자동
취소하고 안내 문구를 띄우도록 수정.

**4) 곡 개별 삭제 시 STRATEGY 가 엉뚱한 곡을 가리킴**
STRATEGY 는 인덱스 기준인데, 대상보다 앞 곡을 × 로 지우면 인덱스가 밀려
다른 곡이 대상이 됐습니다. 앞 곡 삭제 시 인덱스를 감소시키고, 대상 자신이
지워지면 진행을 취소하도록 수정.

### 이상 없음을 확인한 항목
- 서버: 경로 탈출(`../`, URL 인코딩 우회) 차단, 잘못된 JSON 400 응답,
  부분 병합이 다른 키를 지우지 않음, `null` 로 값 해제 정상
- 미터: maxDiff 0(0 나눗셈), 타임라인 일부 누락, 전원 같은 팀 등
  비정상 입력에서 예외·NaN 없음
- STRATEGY: 빈 후보 풀, 범위 밖 choice, 확정 후 취소, 사용 기록 초기화
- 인식 도구: 플레이어별 fields 개수 불일치·ROI 프레임 밖 → 명확한 오류 메시지,
  `--workers 0` 안전 보정, 4인 결과가 기존과 완전 동일(회귀 없음)
- 곡명에 HTML 태그가 들어가도 스크립트로 실행되지 않음(XSS 방어)

## 데이터 보존 / 프리셋

배포 zip 에는 `state.json` 이 없습니다. 코드를 덮어써도 입력해둔 데이터가
그대로 남습니다. 프리셋은 `presets/` 에 저장되며 역시 덮어쓰기 대상이 아닙니다.

## 자동 순위 (점수 따라 실시간 변동)

추출해둔 점수 타임라인으로 1st~4th 를 실시간으로 다시 매깁니다.
컨트롤 "경기 중" 섹션의 **"자동 순위"** 버튼으로 켭니다.

- **피드 위치는 고정입니다.** 순위가 바뀌어도 화면이 자리바꿈하지 않고 랭크
  라벨만 바뀝니다 — 통합 영상의 크롭이 고정이기도 하고, 화면이 통째로
  움직이면 시청자가 누가 누군지 놓치기 때문입니다
- 순위가 바뀌는 순간 랭크 배지가 살짝 튀어 강조됩니다
  (transform 만 쓰는 컴포지터 전용이라 성능 비용 없음)
- 동점은 같은 등수를 주고 다음 등수를 건너뜁니다 (1st, 1st, 3rd, 4th)
- 타임라인이 없는 슬롯은 순위 계산에서 제외됩니다
- 갱신은 초당 약 8회. 매 프레임 정렬하면 동점 근처에서 라벨이 깜빡이기만
  하고 읽히지 않습니다
- 켜져 있는 동안 컨트롤의 랭크 입력칸은 비활성화되고, 끄면 입력해둔
  수동 랭크로 즉시 돌아갑니다

자동 미터와 독립적으로 동작합니다 — 순위만 켜거나 미터만 켤 수 있습니다.

## 미터·순위가 안 움직일 때

둘 다 **점수 타임라인**에 의존합니다. 원인은 거의 항상 셋 중 하나입니다.

컨트롤 "경기 중 — 영상" 섹션 맨 아래 **"점수 타임라인 진단"** 을 보세요.
슬롯별로 상태가 표시됩니다.

| 표시 | 의미 | 조치 |
|---|---|---|
| ● 초록 | 정상 (샘플 수·최종 점수 표시) | — |
| ○ 회색 | 타임라인 경로 미입력 | 슬롯의 타임라인 칸에 `.scores.json` 경로 입력 |
| ✕ 빨강 | 파일 없음 / 내용 이상 | 경로 오타 확인, `sdvx_score.py run` 을 실제로 돌렸는지 확인 |
| ⚠ 노랑 | 자동 미터·순위 토글이 꺼짐 | 위쪽 "자동 미터" / "자동 순위" 버튼 클릭 |

**가장 흔한 실수**: `sdvx_score.py run` 으로 타임라인을 만들었지만 컨트롤의
슬롯별 "타임라인" 칸에 경로를 안 넣은 경우입니다. 통합 영상 모드에서는
4개 슬롯 각각에 `p1~p4` 경로를 따로 넣어야 합니다.

경로는 `videos/` 기준의 웹 경로입니다 — 파일이
`videos/r1.p1.scores.json` 이면 칸에는 `/videos/r1.p1.scores.json` 을 씁니다.

## 숫자 학습을 빠르게 — make_sheet + batch_learn

`learn` 을 0~9 다 모일 때까지 반복하는 게 제일 번거롭습니다. 프레임을 하나씩
뽑아 점수를 눈으로 읽고 명령을 다시 치는 왕복이 많기 때문입니다.
아래 두 도구로 그 왕복을 한 번으로 줄입니다.

**1) 점수 영역만 모아 한 장으로**

```
python make_sheet.py --video ../videos/match.mp4 --config config.json --step 2 --out sheet.png
```

2초 간격으로 훑어 1번 선수의 점수 영역만 오려내고, 시각 라벨을 붙여
한 장에 격자로 붙입니다. 2분 40초면 80칸 정도가 나옵니다.
`--cols` 로 열 수, `--scale` 로 확대 배율을 조절할 수 있습니다.

**2) 읽은 점수를 한꺼번에 학습**

sheet.png 를 열어 각 칸의 점수를 읽고, `시각=점수` 형식으로 넘깁니다.

```
python batch_learn.py --video ../videos/match.mp4 --config config.json \
    --pairs "0=00000000,2=00970000,4=01940000,6=02910000"
```

항목이 많으면 파일로 넘겨도 됩니다 (한 줄에 하나씩).

```
python batch_learn.py --video ... --config ... --pairs-file pairs.txt
```

프레임 추출과 learn 을 알아서 반복하고, **0~9 가 다 모이면 남은 항목은
건너뛰고 끝냅니다.** 전부 읽을 필요 없이 앞쪽 10~15칸만 읽어서 넣어도
대개 충분합니다.

시트를 전부 읽을 필요는 없습니다. 서로 다른 숫자가 많이 보이는 칸
위주로 10개 안팎만 골라 넣으세요. 부족하면 어떤 숫자가 없는지 알려주니
그때 몇 개 더 추가하면 됩니다.

**큰 숫자의 `1` 은 점수가 100만점을 넘어야 나옵니다** — 곡 후반 시각을
꼭 포함시키세요.

## 메모리 부족 / GPU 가속 오류가 날 때

`Failed to allocate 24883200 bytes` 같은 오류는 **워커를 너무 많이 띄운**
탓입니다. 24,883,200 바이트는 정확히 4320x1920 프레임 한 장 크기이고,
프로세스마다 디코더가 버퍼를 따로 잡기 때문에 코어가 20개라고 20개를
띄우면 메모리가 바닥납니다.

`--workers` 기본값을 **0(자동)** 으로 바꿨습니다. 영상 해상도를 보고
메모리 한도(약 2GB) 안에서 개수를 정합니다.

| 해상도 | 프레임 크기 | 자동 워커 수 |
|---|---|---|
| 4320x1920 (통합 4인) | 23.7MB | 4 |
| 2560x1440 | 10.5MB | 8 |
| 1920x1080 | 5.9MB | 8 |

더 줄이고 싶으면 `--workers 2` 처럼 직접 지정하세요. 워커 수를 바꿔도
결과는 완전히 동일합니다(1/2/4 로 검증 완료).

`d3d11va / dxva2_vld` 경고는 GPU 디코딩 초기화 실패입니다. 동작에는
문제가 없지만(CPU 로 폴백) 로그만 시끄러워서, **GPU 가속을 기본 꺼짐으로
바꿨습니다.** 쓰고 싶으면 `--hwaccel` 을 붙이세요.

한 프레임을 읽지 못해도 전체를 포기하지 않고 다음 프레임으로 넘어가도록
방어 코드도 넣었습니다.

### 워커 수 조정 (메모리가 넉넉할 때)

`--workers` 기본값 0은 **여유 메모리를 실제로 재서** 개수를 정합니다
(psutil 이 있으면 정확히, 없으면 보수적으로 2GB 가정).
64GB PC 라면 4320x1920 통합 영상도 자동으로 코어 수만큼 띄웁니다.

```
pip install psutil    # 없으면 2GB 로 가정해 워커가 적게 잡힙니다
```

직접 지정하면 그 값을 그대로 씁니다. 권장치보다 크면 경고만 남기고 진행합니다.

```
python sdvx_score.py run --video ../videos/match.mp4 --config config.json ^
    --out ../videos/match.scores.json --workers 12
```

**출력 경로는 윈도우 경로로 쓰세요.** `/tmp/...` 같은 리눅스 경로를 주면
"출력 폴더가 없습니다" 로 중단됩니다.

## 최종 점수가 실제와 다를 때 (check / scan)

점수는 **단조 증가 제약**으로 걸러집니다. 그래서 중간부터 인식이 끊기면
값이 그 시점에서 멈추고, "최종 점수" 가 실제보다 낮게 나옵니다.
`run` 이 마지막 구간의 인식 실패를 감지하면 경고를 붙입니다.

**어디서 끊겼는지 찾기**

```
python sdvx_score.py scan --video ../videos/match2.mp4 --config config.json --step 10
```

10초 간격으로 훑어 플레이어별 인식값을 표로 보여주고, 마지막으로 성공한
시점을 알려줍니다. `---` 가 나오기 시작하는 지점이 문제 구간입니다.

**그 시점을 자세히 보기**

```
python sdvx_score.py check --video ../videos/match2.mp4 --config config.json --at 120 --dump crops
```

자릿수별 인식 결과와 신뢰도(0~1)를 보여줍니다. `--dump` 를 주면 잘라낸
점수 영역을 이미지로 저장하니 눈으로 확인할 수 있습니다.

**흔한 원인과 대응**

| 증상 | 원인 | 대응 |
|---|---|---|
| 특정 선수만 일찍 끊김 | 그 화면 배경이 밝아 숫자 대비가 낮음 | 그 구간 프레임으로 `learn --overwrite` 추가 |
| 한 자리만 계속 신뢰도 낮음 | 그 숫자 템플릿이 부실 | 그 숫자가 나오는 프레임으로 재학습 |
| 전 구간 `---` | ROI 좌표가 어긋남 | `check --dump` 로 잘린 영역 확인 |
| 곡 종료 후만 실패 | 리절트 화면이라 점수가 없음 | 정상. 무시해도 됩니다 |

임계값을 낮춰 억지로 통과시킬 수도 있지만(`--threshold 0.35`), 오인식이
늘어나므로 템플릿을 보강하는 쪽이 안전합니다.

## 팀 배지 (자선곡 / STRATEGY)

경기 화면 상단, 각 팀 로고 아래에 "이 곡이 누구 선곡인지 / STRATEGY 로
교체된 곡인지" 를 표시합니다. 컨트롤 "경기 중 - 영상" 섹션 하단에서 조작합니다.

**자동 (기본)**
현재 치는 곡이 어느 팀 선곡인지만 고르면 됩니다.
- 그냥 그 팀 선곡이면 -> 골드 테두리 "자선곡"
- STRATEGY 로 교체된 곡이면 -> 붉은 테두리 "STRATEGY" (자동 판별)

STRATEGY 교체는 확정 시점에 기록되므로 따로 표시할 필요가 없습니다.

**수동**
자동이 안 맞거나 예외 상황일 때 좌·우 문구를 직접 지정합니다.
버튼으로 "자선곡" / "STRATEGY" / "지우기" 를 즉시 전환할 수 있습니다.

배지는 **한 번에 한 팀만** 표시됩니다. 왼쪽을 켜둔 상태에서 오른쪽 버튼을
누르면 왼쪽은 자동으로 사라집니다(곡 하나는 한 팀의 선곡이므로).
"지우기" 는 그 자리만 비우고 반대편은 건드리지 않습니다.

문구가 비어 있으면 배지 자체가 숨겨져 빈 상자가 남지 않습니다.

**주의 - 편집으로 게임 로고 띠를 잘라내면**
점수 숫자 위치가 위로 올라가 `config.json` 의 `y` 값이 안 맞게 됩니다.
편집 확정 후 프레임을 다시 뽑아 `y` 만 재측정하세요(가로 위치는 안 변하므로
`x` 는 그대로 씁니다).

## 1v1(R2·R4) 경기 화면 비율 수정

기존에 좌우 여백을 %(15%)로만 줘서, 컨테이너 폭만 좁아지고 높이는 그대로라
개별 화면 비율이 2v2 때(0.618)와 달리 0.889 로 훨씬 넓게 늘어났었습니다.

칸 폭을 **2v2 와 완전히 같은 457px 로 고정**했습니다(가변폭 대신
고정값). 남는 자리는 그대로 좌우 여백으로 남고, 프레임 크기는 1경기
(2v2)의 개별 화면과 픽셀 단위로 동일합니다 - playwright 로 실측해
두 경우 plate 화면 밖 초과량이 -29px 로 완전히 같음을 확인했습니다.

## 선수명 줄을 영상 밖으로 (모든 라운드)

기존에는 선수 아이콘·이름이 `.frame` 안에 absolute 로 얹혀 플레이 화면을
가렸습니다. `.feed` 흐름으로 빼내 **영상 아래에 나란히** 놓도록 바꿨습니다.
2v2·1v1·메가믹스 전부 적용되며, 실측으로 영상과 겹치지 않음을 확인했습니다.

## R2 메가믹스 HUD 비율

예시 편집본의 게임 HUD 영역을 픽셀 단위로 실측한 결과 **867 x 260
(비율 3.335)** 였습니다. 그 비율로 영상이 들어오므로 오버레이에서 늘리거나
누르면 안 됩니다.

`.hud-banner` 를 **800 x 240 (비율 3.333)** 고정 크기로 잡았습니다.
HUD 를 쓰는 경기에서는 상단 바 높이가 132px -> 260px 로 자동으로 커지고,
배지·피드 위치도 함께 내려갑니다(`.matchbar.has-hud`).

HUD 를 예시 비율 그대로 키우면 그만큼 영상 세로 공간이 줄어드는 트레이드오프가
있습니다(2v2 기준 658px -> 메가믹스 530px). HUD 를 더 크게/작게 하려면
`.hud-banner` 의 width/height 를 **비율 3.333 을 유지한 채** 조정하고,
`.matchbar.has-hud` 의 height 와 renderMeter 의 feeds top 값(372px)도
같이 맞추세요.

### R2 선수 영상 비율

예시 편집본의 선수 영상 영역도 실측했습니다: **514 x 759 (비율 0.677)**.
2v2 개별 화면(0.694)과 다르므로 메가믹스 전용 크기를 씁니다.

`.feeds.has-hud` 에서 **366 x 540 (비율 0.678)** 고정. 예시 1920x1080 환산
크기는 526x778 이지만 HUD 가 상단을 차지해 세로가 238px 부족하므로,
비율을 지키면서 화면에 들어가는 최대 크기로 잡았습니다.

| 라운드 | 영상 크기 | 비율 |
|---|---|---|
| R1·R3 (2v2) | 457 x 658 | 0.694 |
| R4 (1v1) | 457 x 658 | 0.694 (2v2 와 동일) |
| R2 (메가믹스) | 366 x 540 | 0.678 (예시 실측 0.677) |

세 라운드 모두 실제 영상으로 재생하며 겹침·화면 이탈이 없음을 확인했습니다.


## STRATEGY 사용 제약 제거

원래는 대회 전체에서 1회만 쓸 수 있게 막혀 있었으나, 운영진이 직접
통제하기로 하여 **횟수 제한을 없앴습니다.** 이제 아무 때나, 몇 번이든
양 팀이 각각 STR 버튼으로 발동할 수 있습니다.

남아 있는 제약은 그대로입니다.
- 밴된 곡에는 STR 불가 / STR 대상 곡은 밴 불가
- 동시에 한 곡만 진행 가능(진행 중엔 다른 곡 STR 버튼 비활성)
- 빈 후보 자리 선택 방지

"사용 기록 초기화" 버튼은 더 이상 의미가 없어 제거했습니다.

## 경기 화면 프리셋을 라운드 포맷 하나로 통합

기존에는 "라운드 포맷"(곡 수·팀 배정)과 "영상 프리셋"(크롭·HUD)이 별도
버튼으로 나뉘어 있었습니다. 라운드별 구도가 항상 고정이라 두 단계로 나눌
이유가 없어, **R1·R2·R4 버튼 하나에 전부** 합쳤습니다.

| 버튼 | 곡 수 | 슬롯 | 크롭 | HUD |
|---|---|---|---|---|
| R1(=R3) | 3곡 | 4명 가로 4분할 | 25%씩 | 없음 |
| R2 | 5곡 | 2명 | 상단 HUD 아래 좌우 2분할 | 자동 켜짐 |
| R4 | 2곡 | 2명 가로 2분할 | 50%씩 | 자동 꺼짐 |

기존에 있던 "프리셋: 가로 4분할/2분할/메가믹스/2×2 격자/HUD 끄기" 버튼은
전부 제거했습니다 — 위 표의 조합으로 이미 다 커버됩니다.

HUD 좌표 입력칸(x/y/w/h)은 R2를 눌렀을 때만 나타나고, **실제 영상에 맞춰
미세조정할 때만** 쓰면 됩니다(매 경기 다시 잡을 필요 없음). 이 칸이
값만 표시되고 실제 입력은 반영이 안 되던 버그도 함께 고쳤습니다.


## STR 버튼(배지)을 다시 누르면 취소되도록 수정

진행 중이거나 확정된 곡의 STR 버튼을 다시 누르면, 예전엔 처음(조준) 단계로
**재시작**해버려서 오버레이 카드 연출은 사라지는데 `active` 는 그대로 남아
다른 곡들이 계속 "진행 중"으로 잠긴 채였습니다.

이제 활성화된 곡의 STR 버튼을 다시 누르면 **즉시 취소**됩니다("지금 닫기"와
동일하게 active 를 비움). 이미 확정돼 곡이 교체된 상태라면 그 교체는
그대로 유지되고, 잠금만 풀립니다.


## 전체 교차 검증 (버그 1건 발견 및 수정)

STRATEGY 무제한 사용, 라운드 포맷 통합, HUD, 배지 취소 등 최근 변경분을
실제 브라우저(Playwright)로 조작하며 공격적으로 재검증했습니다.

### 발견한 버그 — 서버 기본 상태에 STRATEGY 스키마 자체가 없었음

`server.js` 의 `DEFAULT_STATE` 에 `strategy`, `match.hudCrop`,
`match.badges` 필드가 아예 없었습니다. 컨트롤 패널이 `if (!state.strategy)`
로 클라이언트에서 임시로 채워 넣고 있어서 겉으로는 문제가 안 드러났지만,
**오버레이가 컨트롤보다 먼저 접속하거나, 서버가 처음 state.json 을 새로
만드는 시점**에는 STRATEGY 관련 키가 통째로 빠진 상태였습니다.

DEFAULT_STATE 에 세 필드를 추가했습니다. 기존에 이미 돌아가고 있던(구버전)
state.json 도 서버 재시작만으로 자동 보충되는 것을 확인했습니다
(`fillDefaults` 가 빠진 키만 채우고 기존 값은 보존).
